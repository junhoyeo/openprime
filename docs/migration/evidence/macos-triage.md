## (ii) details

### (ii)-1 Stop/delete finalize does not cancel scheduled jobs under a symlinked sessions path (stop_cleanup.rs:98-147)
- Mechanism: `session_tree` canonicalizes every member file (stop_cleanup.rs:55, :76). `cancel_scheduled_jobs_for_tree` filters only by `session_file` (:137-141, `session_id: None`). The cron store matches lexically (pa-core cron/store/jobs.rs:119,135; state.rs:99). Jobs carry the worker's raw `store.path` (scheduled_jobs.rs:352). So canonical != raw, and nothing cancels.
- Callers: `finalize_worker_stop` (stop_cleanup.rs:335-365: root-kill/archive stop and the "worker died before its close wrote state" belt), `finalize_owned_stop` (:455-493: an ephemeral client-owned stop), and the passivated-child delete finalize (supervisor/routing.rs:1118).
- User impact on macOS (only when the agent or sessions dir path contains a symlink: `/tmp`, `/var/folders` `$TMPDIR`, a symlinked `~/.prime`, or env overrides through a symlink):
  - Stopping or archiving a root does not cancel its DESCENDANT subagents' `rlm_heartbeat`/cron jobs. Passivated children have no live worker, so this tree walk is their only cancel. The root's own jobs are still cancelled by the worker's close (`cancel_session_scheduled_jobs`, scheduled_jobs.rs:379-409, which matches by active id, session id, and file).
  - When the worker died before its close, the root's jobs also stay `active`.
  - The passivated-child delete leaves the child's jobs active.
  - The jobs stay dormant while the session is not live (the Rust port never wakes on a schedule, stop_cleanup.rs:3-4). They fire again if the session is later resumed or revived (agent_message wake, resume), which contradicts the "stopping must cancel its scheduled jobs so nothing can revive it" contract (:1-2).
  - The owner's default layout (`/Users/junhoyeo/.prime/agent`, no symlink) is NOT affected.
- Origin: upstream (stop_cleanup.rs and the cron store have no fork commits since c4c238ca0). On Linux CI tmp is not a symlink, so it is never exercised.
- Minimal fix idea: also pass `session_id: Some(member.session_id)` in the filter, or canonicalize both sides inside `cancel_jobs_for_session`.

### (ii)-2 `delete_saved_session` with macOS `/usr/bin/trash` (saved_session_commands.rs:113-135)
- Mechanism: `trash -- <path>` is called; `removed_by_trash = status.success() || !path.exists()`.
- Impact:
  - (a) Confirmed by the test: deleting a MISSING file answers `{ok:true, method:"trash"}`, and the job-cancel hook and the ledger tombstone run for a file that never existed. TS-shaped clients cannot see the failure.
  - (b) Likely, not verified: macOS `trash` (ships with macOS 15+) does not accept `--` (it answered "Un-recognized argument --version at index 1"), so it fails for every real file. Every delete then falls back to permanent `unlink`. The Trash safety net is never used, and the answer says `method:"unlink"`.
- Suggested probe (not run, read-only role): `touch /tmp/x.jsonl; /usr/bin/trash -- /tmp/x.jsonl; echo $?; ls /tmp/x.jsonl`.
- Origin: upstream.

## Path-canonicalization review (requested)
- Consistent (canonical on both sides): lease identity (lease.rs:73/117/517/439; hold_refusal.rs:65-68), registry `find_by_session_file` (registry.rs:403), session bindings (session_bindings.rs:116), ledger edge joins (rlm_ledger.rs:289-448, 697-725), saved-session own-file and live checks (saved_session_commands.rs:868/914), stop-tree coverage sets (stop_cleanup.rs:105-111, 257-276), roster seed root matching (supervisor_roster_seed.rs:47/236/255/264). The fork's lease.rs change (be7a229d3) removed the one real identity-split risk in the lease layer.
- Mismatch that matters: canonical (supervisor) vs lexical (cron store) -> (ii)-1.
- Note A, potential, not test-backed, low: `rlm_ledger_path` hashes `canonicalize_dir(sessions_dir)` (rlm_ledger.rs:126-129; replay.rs:344-347), which is realpath when the dir exists and raw otherwise. If the sessions dir under a symlink does not exist yet when the path is first computed, the ledger file hash differs from the later canonical hash, and edges written early are invisible later. This is the same bug class that be7a229d3 fixed for leases. Spawns normally happen after the sessions dir exists, so the risk is low. Upstream.
- Note B, wire form, low: ledger-derived rows publish canonical paths (`rlm_roster.rs:190 parentSessionPath`, roster seed rows, `session_binding.sessionFile`). Scan rows, `get_session_stats`, and create publish raw paths. pa-tui joins file keys lexically (`agents_view_state.rs:83-101`, comment "TS canonicalizes"; `subagents.rs:131-157 depth_consistent_binding`). Under a symlinked sessions dir, the `file:` key of a ledger child does not match its parent's raw `sessionFile`. Lineage probably still links through `active:`/`session:` keys (passive rows carry `parentActiveSessionId`), so the visible impact is unconfirmed. Upstream.
